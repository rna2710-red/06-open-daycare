# /a11y — Accessibility audit (WCAG 2.2 AA)

You are invoking the `accessibility-checker` agent.

Input: `$ARGUMENTS`

- If empty: ask which file to review (`.tsx`, `.jsx`, `.html`, `.css`).
- If it names a file (path or basename): audit that file.

Follow the `accessibility-checker` agent instructions end-to-end:

1. Load design tokens from `app/globals.css` and collect color pairs used in the target file.
2. Static WCAG 2.2 AA audit for React/TSX and pure HTML/CSS.
3. Design-system contrast verification with WCAG ratios (4.5:1 text / 3:1 large text & UI).
4. Playwright runtime checks (a11y tree, keyboard, focus, computed colors) when the UI is reachable.
5. Fix component-level issues; propose (do not silently apply) global token changes.
6. Re-verify lint/contrast as needed.
7. Output the final report in Spanish.
